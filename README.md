# 🧴 اي كيو — محلل المخزون الذكي

**إصدار تجريبي** · متجر **أرياف للعطور**

نظام يحلل مبيعات متجرك، **يتنبأ بالطلب القادم بالذكاء الاصطناعي**، ثم يخبرك:
ماذا تطلب؟ ومتى؟ وكم كمية؟ — بواجهة عربية كاملة.

النسخة الحالية تعمل على جهازك ببيانات متجر عطور تجريبية
(**20 منتج** × **180 يوم** مبيعات يومية)، وهي مبنية بحيث نستبدل البيانات
ببيانات سلة الحقيقية لاحقاً دون إعادة كتابة أي شيء.

---

## 1. المتطلبات قبل البدء

تحتاج شيئاً واحداً فقط: **Python نسخة 3.10 أو أحدث**.

للتأكد أنه مثبّت عندك، افتح **Terminal**:

- **ويندوز:** اضغط زر ويندوز → اكتب `cmd` → افتح **Command Prompt**
- **ماك:** اضغط `Command + Space` → اكتب `Terminal` → Enter

ثم اكتب:

```bash
python --version
```

| ما يظهر لك | ماذا تفعل |
|---|---|
| `Python 3.10.x` أو أعلى | ممتاز، انتقل للخطوة 2 |
| `Python 2.7.x` | جرّب `python3 --version` واستخدم `python3` في كل الأوامر |
| `command not found` أو لا شيء | حمّل بايثون من [python.org/downloads](https://www.python.org/downloads/) وفي ويندوز **ضع علامة ✅ على Add Python to PATH أثناء التثبيت** |

## 3. إنشاء بيئة افتراضية (Virtual Environment)

**ما هي؟** صندوق منفصل نضع فيه مكتبات هذا المشروع فقط، حتى لا تتعارض مع مشاريع أخرى.

```bash
python -m venv venv
```

لن يظهر شيء — هذا طبيعي. سيُنشأ مجلد جديد اسمه `venv`.

ثم **فعّل البيئة**:

```bash
venv\Scripts\activate        # ويندوز
source venv/bin/activate     # ماك أو لينكس
```

**علامة النجاح:** ستظهر كلمة `(venv)` في بداية سطر Terminal.

> 🔴 في ويندوز إذا ظهر خطأ `running scripts is disabled`، افتح PowerShell كمسؤول ونفّذ:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ثم أعد المحاولة.

**ماذا يفعل؟** يحمّل المكتبات السبع التي يحتاجها المشروع (Streamlit للواجهة،

> من scikit-learn. احذف سطر lightgbm من `requirements.txt` وأعد الأمر.

## 5. تشغيل المشروع

```bash
streamlit run app.py
```

> ⚠️ **لا تستخدم** `python app.py` — تطبيقات Streamlit تُشغّل بالأمر أعلاه فقط.

**ماذا يحدث؟**
1. يولّد بيانات متجر العطور التجريبية (أول مرة فقط، ~ثانية)
2. يدرّب نموذج الذكاء الاصطناعي على المبيعات (~5 ثوانٍ)
3. يفتح المتصفح تلقائياً على `http://localhost:8501`

**علامة النجاح:** يظهر في Terminal:

```
You can now view your Streamlit app in your browser.
Local URL: http://localhost:8501
```

إذا لم يفتح المتصفح وحده، انسخ الرابط والصقه بنفسك.

**لإيقاف المشروع:** اضغط `Ctrl + C` داخل Terminal.

## 6. ماذا سترى في الواجهة؟

القائمة الجانبية **على اليمين**، وفي أعلاها مباشرة زر **🤖 توصية الذكاء الاصطناعي**
الذي يعطيك ملخص حالة المتجر كاملاً وأهم 3–4 إجراءات مرتبة حسب الأولوية.

| التبويب | المحتوى |
|---|---|
| **نظرة عامة** | مؤشر صحة المخزون من 100، بطاقات (نفاد وشيك / يحتاج طلب / راكد / آمن)، وجدول كل المنتجات |

| **تفاصيل المنتج** | كم بعت في آخر 7 و14 و30 يوم، رسم المبيعات + التنبؤ، وشرح التوصية خطوة بخطوة |
| **توصيات المواسم** | اليوم الوطني، رمضان، عيد الفطر، عيد الأضحى — وآخر موعد للطلب قبل كل موسم |

salla-ai-inventory/

├── requirements.txt          ← قائمة المكتبات
├── README.md                 ← هذا الملف

│   ├── data_source.py        ← طبقة مصادر البيانات (ديمو الآن، سلة لاحقاً)
│   ├── preprocessing.py      ← تنظيف البيانات وهندسة الخصائص
│   ├── forecasting.py        ← نموذج التنبؤ بالطلب (ML)

## 8. كيف يعمل الذكاء الاصطناعي؟

### أ) المشكلة
النموذج لا يفهم "تاريخ" ولا "منتج" — يفهم **أرقاماً** فقط.
لذلك نحوّل كل يوم مبيعات إلى صف من الأرقام يصف الماضي.

### ب) الخصائص (Features) — 19 خاصية

| المجموعة | الخصائص | تعني |
|---|---|---|
| المبيعات السابقة | `sales_lag_1/3/7/14/30` | كم بعت أمس، وقبل 3 و7 و14 و30 يوم |
| المتوسطات | `rolling_mean_7/14/30` | متوسط مبيعاتي في آخر أسبوع/أسبوعين/شهر |
| التذبذب | `rolling_std_7/30` | هل مبيعاتي مستقرة أم متقلبة |
| التقويم | `day_of_week`, `day_of_month`, `month`, `weekend` | أثر أيام الأسبوع ونهاية الأسبوع |
| التجارة | `promotion`, `price`, `price_change` | العروض والأسعار |
| الاتجاه | `trend` | متوسط 7 أيام ÷ متوسط 30 يوم (أكبر من 1 = صعود) |

### ج) منع تسريب البيانات (Data Leakage)
أخطر خطأ في مشاريع التنبؤ: أن يرى النموذج مبيعات اليوم وهو يحاول توقّعه —
فتظهر دقة خيالية في الاختبار ثم يفشل في الواقع.
منعنا ذلك بـ **`shift(1)`**: كل خاصية تُحسب من الماضي فقط.

### د) التقسيم الزمني (وليس العشوائي)
- **التدريب:** أول ~159 يوم
- **الاختبار:** آخر **21 يوم** لم يرها النموذج إطلاقاً

لأن التقسيم العشوائي يعني التدريب على المستقبل — وهذا غش.

### هـ) النموذج
**LightGBM** بهدف `poisson` (لأن المبيعات أعداد صحيحة موجبة).
نموذج واحد يتعلم من كل المنتجات معاً، فيستفيد المنتج قليل المبيعات من أنماط بقية المنتجات.

### و) القياس
- **MAE** = كم وحدة نخطئ في المتوسط
- **WAPE** = نسبة الخطأ من إجمالي المبيعات (كلما قلّت كان أفضل)

ونقارن دائماً بـ **Baseline** (متوسط متحرك 7 أيام + متوسط أسّي).
النموذج الحالي يتفوق بحوالي **16%** على أفضل طريقة تقليدية.

هذه أرقام تقنية لا تظهر في الواجهة حتى لا تشوّش على التاجر. لرؤيتها شغّل:

```bash
python -m src.forecasting
```

## 9. رحلة البيانات: من المبيعات إلى قرار الشراء

```
مبيعات تاريخية (CSV)
        ↓  data_source.py — من أين نقرأ البيانات
        ↓  preprocessing.py — تنظيف + 19 خاصية
        ↓  forecasting.py — LightGBM يتدرب ثم يتنبأ يوماً بيوم لـ 30 يوم
        ↓  inventory.py — المعادلات:
              الطلب خلال مدة التوريد = متوسط الطلب اليومي × مدة التوريد
              مخزون الأمان            = Z × انحراف الطلب × √مدة التوريد
              نقطة إعادة الطلب        = الطلب خلال مدة التوريد + مخزون الأمان
              وضع المخزون            = المتوفر + قيد الشحن − المحجوز
              احتمال النفاد          = محاكاة Monte Carlo بـ 3000 سيناريو
        ↓  recommendations.py — تحويل الأرقام إلى جُمَل مفهومة
        ↓  app.py — الداشبورد
```

**مثال حقيقي من الديمو:**
> منتج *عطر العنبر الملكي*: المتوفر **52** وحدة، الطلب المتوقع **22.5** وحدة يومياً،
> أي تغطية **2.1 يوم** فقط، بينما مدة التوريد **10 أيام** →
> احتمال النفاد **100%** → **اطلب 552 وحدة الآن**.

## 10. أين الذكاء الاصطناعي وأين الشرح؟ (نقطة مهمة)

| المهمة | من ينفذها |
|---|---|
| التنبؤ بالطلب | نموذج **LightGBM** — تعلّم آلة حقيقي |
| حساب مخزون الأمان ونقطة الطلب | **معادلات Python** |
| احتمال النفاد | **محاكاة Monte Carlo** |
| صياغة الشرح للتاجر | **قوالب نصية** في `recommendations.py` |

**لا يوجد أي نموذج لغوي (LLM) يحسب أرقاماً.** طبقة الشرح تقرأ الأرقام الجاهزة فقط.
لاحقاً يمكن استبدالها بـ LLM لصياغة أجمل، دون أي تغيير في الحسابات.

## 11. توصيات المواسم

سوق العطور موسمي بشدة، والمورد يحتاج وقتاً. لذلك يحسب النظام لكل مناسبة:

```
الطلب المتوقع في الموسم = متوسط الطلب اليومي × أيام الموسم × معامل الزيادة للفئة
آخر موعد للطلب          = بداية الموسم − مدة التوريد − 3 أيام احتياط
```

| المناسبة | أعلى الفئات ارتفاعاً |
|---|---|
| **اليوم الوطني** | الهدايا ×1.6 · معطرات المنزل ×1.45 · العطور الرجالية ×1.35 |
| **رمضان** | البخور ×2.2 · العود والدهن ×1.9 · المسك ×1.65 |
| **عيد الفطر** | الهدايا ×2.6 · العطور الفاخرة ×2.4 · النسائية ×2.1 |
| **عيد الأضحى** | العود والدهن ×1.95 · الهدايا ×1.8 · البخور ×1.75 |

**مهم:** هذه المعاملات تقديرات لسوق العطور السعودي، وتُعدّل بسهولة من
`src/seasonality.py`. عند توفر بيانات مبيعات **سنة كاملة أو أكثر** يستطيع النظام
استخراجها من مبيعاتك الفعلية بدل التقدير. التواريخ الهجرية تقريبية وتخضع لرؤية الهلال.

## 12. حل المشاكل الشائعة

| الخطأ | الحل |
|---|---|
| `'streamlit' is not recognized` | لم تفعّل البيئة الافتراضية — أعد خطوة 3 وتأكد من ظهور `(venv)` |
| `ModuleNotFoundError: No module named 'src'` | شغّل الأمر من **داخل مجلد المشروع** وليس من مجلد آخر |
| `ModuleNotFoundError: No module named 'lightgbm'` | لا يعطّل المشروع؛ سيستخدم البديل. أو `pip install lightgbm` |
| `Port 8501 is already in use` | `streamlit run app.py --server.port 8502` |
| الصفحة بيضاء أو عالقة | انتظر 10 ثوانٍ (يدرّب النموذج)، ثم حدّث الصفحة |
| أريد بيانات جديدة | احذف مجلد `data` وأعد التشغيل |
| تعديل لم يظهر | اضغط **Rerun** أعلى الصفحة أو `Ctrl+C` وأعد التشغيل |

## 13. الخطوة القادمة: ربط سلة

الكود جاهز من الآن: في `src/data_source.py` يوجد كلاس `SallaDataSource` فارغ
بجانب `DemoCSVDataSource`. كلاهما يلتزم بنفس الأعمدة بالضبط.

عند الربط لاحقاً نضيف: **OAuth 2.0** → **Merchant API** لسحب المنتجات والطلبات →
**Webhooks** لتحديث المخزون لحظياً، ثم نغيّر سطراً واحداً في `app.py`:

```python
sales_df, products_df = load_store_data("salla")   # بدل "demo"
```

**ولا نغيّر أي سطر** في `preprocessing.py` أو `forecasting.py` أو `inventory.py`.
